# Test Queries Template

**Purpose:** Systematically test skill triggering accuracy with positive and negative test cases.

**Format:** Each line is either a test query OR a comment (starts with #)
- SHOULD_TRIGGER | [query text that should activate your skill]
- SHOULD_NOT_TRIGGER | [query text that should NOT activate your skill]

**Target:** 90%+ triggering accuracy (correct activation on SHOULD_TRIGGER, correct skip on SHOULD_NOT_TRIGGER)

---

## How to Use This Template

1. **Copy this template** for your specific skill
2. **Customize the SHOULD_TRIGGER examples** - Add 8-12 queries that should activate your skill
   - Include direct requests ("Do X")
   - Include implicit requests ("I need to Y")
   - Include domain-specific phrasing your users would say
   - Include edge cases (abbreviated terms, misspellings if common)
3. **Customize the SHOULD_NOT_TRIGGER examples** - Add 8-12 queries that should NOT activate
   - Include similar domain but wrong skill (e.g., "debug code" when skill is "review code")
   - Include unrelated requests
   - Include ambiguous queries (could be multiple skills, yours shouldn't dominate)
4. **Run the test** - Paste each query into Claude and observe which skill (if any) triggers
5. **Calculate accuracy** - % of SHOULD_TRIGGER that triggered + % of SHOULD_NOT_TRIGGER that didn't trigger / total queries
6. **Iterate on description** if accuracy < 90%

## Iteration Tips

### If accuracy < 90%:

**Problem:** Too many false positives (triggers when it shouldn't)
**Solution:** Make description more specific
- Add exclusions: "Use when [X], NOT for [Y]"
- Narrow domain: Be specific about what actions the skill performs
- Add qualifying context: "Use when user needs to [specific workflow]"

**Problem:** Too many false negatives (doesn't trigger when it should)
**Solution:** Make description broader or add trigger keywords
- Include common phrasings users might use
- Add domain terminology to description
- Cover both direct ("create sprint") and implicit ("what should we build?") requests

**Problem:** Conflicts with other skills
**Solution:** Coordinate descriptions to have clear boundaries
- Your skill: "Use for sprint PLANNING (creating new sprints)"
- Other skill: "Use for sprint REPORTING (analyzing completed sprints)"
- Clear distinction prevents overlap

### Testing Cadence

- **Initial development:** Test every description change
- **After launch:** Test monthly with real user queries
- **After major changes:** Re-test full suite

### Real User Queries

After skill is deployed, collect actual user queries that should have triggered but didn't:
- Add them to SHOULD_TRIGGER section
- Re-test and iterate description
- Builds real-world triggering accuracy

**Minimum test suite:**
- 8 SHOULD_TRIGGER queries
- 8 SHOULD_NOT_TRIGGER queries
- Target: 90%+ accuracy (14/16 correct)

- 12 SHOULD_TRIGGER queries
